2. Method

Static reading of the repository: cryptographic calls whose algorithm is written out, key material and certificates present in the tree, server and framework configuration, deployment scripts, declared dependencies.

Network probe: an ordinary TLS handshake, the same one a browser performs, against the declared hosts. It establishes what is actually negotiated, which the repository can contradict in either direction.

The inventory is then crossed with how long each kind of data has to stay confidential. The reasoning is Mosca's inequality (2015), simplified:

year of the analysis + declared confidentiality lifetime > expiry of the algorithm ⟹ the data already emitted is exposed, and migrating does not repair it

The analysis is reproducible: the same command on the same state of the repository produces the same digest of findings. The tool does not predict the arrival of a quantum computer; it uses the regulatory deadline as its planning date.

3. Limits of the analysis

These limits appear in the body of the report rather than in a footnote: an inventory that does not say what it failed to look at is not an inventory.

  • the cryptography of your managed services — database, object storage, TLS terminated by an intermediary — appears in no file of this repository
  • what is actually negotiated at runtime, for any host not declared in the probe section
  • keys held in an HSM or by a provider
  • the real lifetime of the data: it comes from your declaration, not from the code — an undeclared domain is computed with a default lifetime of 0 years
  • The system's service horizon is not declared: the calculation assumes it stops writing data today. That is the optimistic reading — a service still in production in ten years will produce ten more years of data to protect. Add `service_until` to the declaration.
  • Expiry used: 2035, after NIST IR 8547. Another regime — institutional, defence — gives another date: see `regime` in the declaration.
  • Binary files (images, fonts, archives) are read over their first few megabytes only, and only for three verifiable signs: a key block, bytes after the end of the image, an extension that lies about the content. A message hidden in the bits of an image is not detected here, and does not claim to be.
  • YAML configuration files are read as text, not interpreted: an algorithm set through a parameter, an imported file or an environment variable is not seen here.
  • Published vulnerabilities in dependencies were not checked: run `sablier advisories <path>`, then `--advisories=<file>`. Without it, a library with a hole in it today is presented as plain inventory.
  • Findings of medium confidence are marked as such: there the algorithm comes from a variable or a configuration value, and could not be established by reading alone.

8. Conclusion and recommendations

  1. Nothing urgent, and that is a result

    No long-lived data is exposed to harvesting, and nothing is broken today. Doing nothing is the right decision here: replacing cryptography that holds costs time, introduces risk and improves nothing.

  2. Put this report back on the calendar

    The window closes by itself: the expiry date does not move (2035), but every year that passes brings your data closer to that line. A domain that is clear today with a nine-year lifetime will not be next year. Re-running the analysis once a year is enough — and checking, while you are there, that the regulatory deadline has not moved.

9. Glossary

The seven terms needed to read this report.

Harvest now, decrypt later
Capturing encrypted data today in order to decrypt it when a machine able to do so exists. For that data, the date of compromise is the day it was encrypted, not the day of the attack.
Confidentiality
What encryption protects: the data stays unreadable. It is the only property exposed to harvesting.
Authenticity
What a signature protects: the origin is established. A signature cannot be captured now and forged later; the urgency concerns only long-lived trust anchors.
Confidentiality lifetime
The number of years a kind of data has to stay secret. It is declared by the commissioning party; no tool can derive it from the code.
Expiry
The year from which an algorithm must no longer protect confidential data. Taken here from the texts cited in section 4.
Symmetric / asymmetric
Symmetric cryptography (AES, ChaCha20) is not the subject: a quantum computer narrows its margin without breaking it. The problem is asymmetric cryptography: RSA, elliptic curves, key exchange.
Hybridisation
Combining a classical algorithm with a post-quantum one, so that the protection holds if either falls. It is the position of the authorities during the transition.
